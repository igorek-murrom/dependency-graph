# Практическая работа № 2, вариант 16

Инструмент визуализации графа зависимостей пакетов Rust (Cargo).
Текущий этап: **1 — минимальный прототип с конфигурацией**.

Программа читает шесть параметров из CSV, проверяет их и выводит
в формате `ключ=значение`. При ошибке пишет сообщение в stderr
и завершается с кодом 2. При успешном запуске возвращает код 0.
Проверка останавливается на первой найденной ошибке.

Получение зависимостей, обход графа и визуализация относятся к следующим
этапам. Сейчас сетевые запросы не выполняются, тестовый граф не разбирается,
изображение и ASCII-дерево не создаются. Менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются.

## Требования и запуск

Python 3.10 или новее, для `run.sh` — совместимая с POSIX оболочка.
Программа и тесты используют только стандартную библиотеку Python.
Устанавливать зависимости и выполнять отдельную сборку не требуется.

Из корня проекта:

```sh
./run.sh examples/config.csv
./run.sh examples/test-config.csv
./run.sh --help
```

Альтернативный запуск без оболочки:

```sh
python3 src/main.py examples/config.csv
```

Единственный аргумент приложения — путь к CSV. Сами настройки берутся
только из этого файла. Путь к CSV считается от текущей рабочей папки.
Пути **внутри CSV** считаются от папки этого CSV; абсолютные пути допустимы.

Вывод первого примера:

```text
package_name=serde
repository=https://index.crates.io/
test_mode=false
output_file=graph.svg
ascii_tree=false
filter_substring=
```

## Формат и настройки

Кодировка CSV — UTF-8, допускается BOM. Разделитель — запятая.
Первая строка строго `key,value`. Далее каждый из шести ключей должен
встречаться ровно один раз; порядок произвольный. Неизвестные ключи,
лишние столбцы и пустые строки считаются ошибкой.
Значения с запятой заключаются в двойные кавычки по правилам CSV.
Управляющие символы в значениях, включая перенос строки и табуляцию,
запрещены. Пробелы автоматически не удаляются.

```csv
key,value
package_name,serde
repository,https://index.crates.io/
test_mode,false
output_file,graph.svg
ascii_tree,false
filter_substring,
```

| Ключ | Назначение и проверка |
| --- | --- |
| `package_name` | Имя пакета: латинские буквы, цифры, `_`, `-`; первый символ — буква или цифра. |
| `repository` | При `test_mode=false`: HTTP(S)-URL с хостом, без пробелов и учётных данных. |
| `test_mode` | Режим тестового репозитория: строго `true` или `false`. |
| `output_file` | Непустой путь к SVG-файлу; родительская папка должна существовать. |
| `ascii_tree` | Включение вывода ASCII-дерева на этапе визуализации: `true` или `false`. |
| `filter_substring` | Подстрока исключения пакетов на этапе обхода графа. Пустая строка отключает фильтр. |

При `test_mode=true` параметр `repository` должен указывать на существующий
доступный для чтения файл. В примере `test-config.csv` это
`repository.json` с пакетами `A`, `B`, `C`. На первом этапе проверяется
только доступность файла, его содержимое будет использоваться на этапе 3.
URL проверяется синтаксически; доступность сервера пока не проверяется.
Расширение `.svg` проверяется без учёта регистра. Программа пока
не проверяет возможность записи изображения и не перезаписывает файлы.

## Проверка и демонстрация ошибок

Все тесты запускаются из корня проекта:

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют оба режима, все параметры, отсутствие каждого ключа,
неверные флаги, URL и пути, повреждённый CSV, дубликаты, неизвестные ключи,
неверную кодировку, BOM, кавычки, вывод CLI и коды завершения.
Сеть для тестов не требуется.

Для ручной демонстрации в `examples/errors/` лежат конфигурации
с одной ошибкой в каждой. Следующие команды должны завершиться с кодом 2:

```sh
./run.sh examples/errors/package_name.csv
./run.sh examples/errors/repository.csv
./run.sh examples/errors/test_mode.csv
./run.sh examples/errors/output_file.csv
./run.sh examples/errors/ascii_tree.csv
./run.sh examples/errors/filter_substring.csv
```

| Файл | Ошибка |
| --- | --- |
| `package_name.csv` | Недопустимый символ `/` в имени пакета. |
| `repository.csv` | Строка вместо HTTP(S)-URL. |
| `test_mode.csv` | `yes` вместо `true` или `false`. |
| `output_file.csv` | Расширение `.png` вместо `.svg`. |
| `ascii_tree.csv` | `yes` вместо `true` или `false`. |
| `filter_substring.csv` | Перенос строки внутри значения в кавычках. |

Пример сообщения:

```text
Ошибка конфигурации: ascii_tree: ожидается true или false
```

## Структура и функции

```text
src/
  config.py           Чтение и проверка настроек
  main.py             CLI
tests/               Автоматические тесты
examples/
  config.csv          Обычный режим
  test-config.csv     Тестовый режим
  repository.json     Пример локального репозитория
  errors/             Ошибки каждого параметра
run.sh                Скрипт запуска
.gitignore            Исключения Git
README.md             Документация
```

В `src/config.py`:

- `Config` — неизменяемая структура из шести проверенных параметров.
- `ConfigError` — ошибка чтения или проверки конфигурации.
- `read_values(path)` — чтение CSV и проверка наличия всех ключей.
- `collect_rows(rows)` — проверка столбцов, ключей, повторов и символов.
- `parse_bool(name, value)` — преобразование `true`/`false` в булево значение.
- `resolve_path(value, base)` — разрешение пути относительно папки CSV.
- `validate_repository(value, test_mode, base)` — проверка URL или файла.
- `validate_output(value, base)` — проверка имени SVG и родительской папки.
- `load_config(path)` — полная проверка и создание `Config`.

В `src/main.py` функция `main(argv=None)` обрабатывает аргументы,
загружает настройки, выводит их или сообщение об ошибке и возвращает
код завершения. `run.sh` передаёт аргументы этой точке входа.

## Работа с Git

Первый этап выполняется в ветке `stage-1`. Каждый следующий этап
будет выполняться в отдельной ветке от проверенного коммита предыдущего.
Коммиты создаются после проверки владельцем проекта, с подробным сообщением
в формате Conventional/Scoped Commits, например `feat(config): ...`.
Для сдачи по условию потребуется публичный Git-репозиторий.

`условие.pdf`, служебные файлы Python, настройки редакторов и результаты
сборки исключены через `.gitignore`. Будущие изображения можно сохранять
в игнорируемую папку `output/` (её нужно предварительно создать)
или рядом с примерами CSV.
