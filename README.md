# Практическая работа № 2, вариант 16

Программа для работы с графом зависимостей пакетов Rust (Cargo).
На первом этапе она читает настройки из CSV, проверяет их и выводит
в формате `ключ=значение`. Получение зависимостей и построение графа
будут добавлены на следующих этапах.

## Запуск

Нужен Python 3.10 или новее. Дополнительные библиотеки и сборка не нужны.
Команды выполняются из папки проекта:

```sh
./run.sh examples/config.csv
```

Можно запустить напрямую:

```sh
python3 src/main.py examples/config.csv
```

Для тестового режима есть пример `examples/test-config.csv`.
Справка вызывается командой `./run.sh --help`.

## Настройки

Путь к CSV передаётся при запуске. Все настройки задаются внутри файла:

```csv
key,value
package_name,serde
repository,https://index.crates.io/
test_mode,false
output_file,graph.svg
ascii_tree,false
filter_substring,
```

- `package_name` — имя пакета: латинские буквы, цифры, `_` и `-`.
  Первый символ должен быть буквой или цифрой.
- `repository` — HTTP(S)-адрес репозитория без пробелов и учётных данных.
  В тестовом режиме вместо адреса указывается путь к доступному файлу.
- `test_mode` — работа с тестовым репозиторием: `true` или `false`.
- `output_file` — имя будущего SVG-файла. Папка для него должна существовать.
- `ascii_tree` — вывод зависимостей в виде ASCII-дерева: `true` или `false`.
- `filter_substring` — подстрока для исключения пакетов из анализа.
  Пустое значение отключает фильтр.

CSV должен быть в UTF-8 с заголовком `key,value`. Каждый параметр
указывается один раз. Неизвестные ключи, лишние столбцы и управляющие
символы считаются ошибкой. Значения с запятой нужно заключать в кавычки.
Пути внутри CSV считаются относительно папки этого файла.

На первом этапе проверяются только настройки. Репозиторий не загружается,
содержимое тестового файла не разбирается, изображение не создаётся.

Пример вывода:

```text
package_name=serde
repository=https://index.crates.io/
test_mode=false
output_file=graph.svg
ascii_tree=false
filter_substring=
```

## Ошибки

При неверных настройках программа выводит сообщение об ошибке
и завершается с кодом 2. При успешном запуске код завершения — 0.

В `examples/errors/` есть примеры ошибок для каждого параметра.
Например:

```sh
./run.sh examples/errors/ascii_tree.csv
```

Результат:

```text
Ошибка конфигурации: ascii_tree: ожидается true или false
```

## Файлы и функции

Исходники находятся в `src/`, примеры настроек — в `examples/`,
проверки — в `tests/`. Скрипт `run.sh` запускает программу.

В `src/config.py` структура `Config` хранит настройки, а `ConfigError`
описывает ошибки их чтения и проверки. Функции этого модуля:

- `read_values` — читает CSV и проверяет наличие параметров.
- `collect_rows` — собирает настройки в словарь.
- `validate_row` — проверяет столбцы, ключи и повторы.
- `validate_printable` — проверяет отсутствие управляющих символов.
- `parse_bool` — преобразует `true` и `false` в булевы значения.
- `resolve_path` — определяет путь относительно папки CSV.
- `validate_repository` — выбирает проверку URL или локального файла.
- `validate_local_repository` — проверяет доступность файла для чтения.
- `parse_repository_url` — разбирает адрес, проверяет схему, хост и порт.
- `validate_url_access` — проверяет учётные данные и номер порта.
- `validate_remote_repository` — проверяет URL, включая пробелы.
- `validate_output` — проверяет имя и расширение выходного файла.
- `validate_output_location` — проверяет папку и тип выходного пути.
- `load_config` — проверяет все настройки и создаёт `Config`.

В `src/main.py` функция `main` обрабатывает аргументы запуска,
загружает настройки и выводит результат или ошибку.

Команда запуска проверок:

```sh
python3 -m unittest discover -s tests -v
```
