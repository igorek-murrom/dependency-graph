# Практическая работа № 2, вариант 16

Программа строит граф зависимостей пакетов Rust (Cargo).
На третьем этапе добавлены транзитивные зависимости, фильтрация
и работа с тестовым JSON-репозиторием. Обход выполняется алгоритмом
DFS через стек, без рекурсии. Циклы сохраняются и не мешают завершению.

## Запуск

Нужен Python 3.10 или новее. Дополнительные библиотеки и сборка не нужны.
Команды выполняются из папки проекта:

```sh
./run.sh examples/test-config.csv
```

Можно запустить напрямую:

```sh
python3 src/main.py examples/test-config.csv
```

Для настоящего репозитория нужен интернет:

```sh
./run.sh examples/cargo-config.csv
```

В этом примере выбран небольшой пакет `adler2`. Пример с `serde`
сохранён в `examples/config.csv`; полный граф может быть большим,
так как учитываются и необязательные зависимости, и зависимости разработки.
Справка вызывается командой `./run.sh --help`.

## Настройки

При запуске передаётся путь к CSV с настройками:

```csv
key,value
package_name,A
repository,repository.json
test_mode,true
output_file,test-graph.svg
ascii_tree,false
filter_substring,
```

- `package_name` — имя пакета. Для Cargo допустимы латинские буквы,
  цифры, `_` и `-`; первый символ — буква или цифра.
  В тестовом режиме используются только заглавные латинские буквы.
- `repository` — HTTP(S)-адрес корня индекса Cargo, например
  `https://index.crates.io/`, без пробелов, учётных данных, query и fragment.
  В тестовом режиме это путь к JSON-файлу.
- `test_mode` — использование тестового репозитория: `true` или `false`.
- `output_file` — имя будущего SVG-файла. Папка должна существовать.
- `ascii_tree` — настройка вывода ASCII-дерева: `true` или `false`.
- `filter_substring` — подстрока для исключения пакетов из анализа.
  Пустое значение отключает фильтр. Регистр учитывается.

CSV должен быть в UTF-8 с заголовком `key,value`. Каждый параметр
указывается один раз. Неизвестные ключи, лишние столбцы и управляющие
символы считаются ошибкой. Значения с запятой заключаются в кавычки.
Пути внутри CSV считаются относительно папки этого файла.

Исключённые пакеты не загружаются и не попадают в граф. Если через них
проходил единственный путь к другим пакетам, эти пакеты тоже не обходятся.
Общая зависимость сохраняется, если к ней есть другой доступный путь.
При исключении корня программа сообщает, что граф пуст.

В Cargo имена приводятся к нижнему регистру. Для каждого пакета выбирается
последняя стабильная неотозванная версия. Учитываются все объявленные
зависимости: normal, build, dev, optional и зависимости отдельных платформ.
Это граф по именам пакетов; требования к версиям, features и целевая
платформа не разрешаются так, как при установке через Cargo.
Зависимость из другого реестра приводит к сообщению об ошибке.

SVG и ASCII-дерево относятся к этапу 5. Сейчас `output_file` и `ascii_tree`
только проверяются, а граф выводится списками смежности в порядке DFS.

## Тестовый репозиторий

JSON описывает пакеты и их прямые зависимости:

```json
{
  "A": ["B"],
  "B": ["C"],
  "C": []
}
```

У каждого упомянутого пакета должно быть описание. Пустой массив означает,
что зависимостей нет. Имена состоят из A-Z; допустимы и многобуквенные имена.
Повторные JSON-ключи считаются ошибкой, повторные рёбра объединяются.
Циклы и ссылки пакета на самого себя допустимы.

JSON указывается в параметре `repository`. При запуске передаётся CSV,
а не сам JSON. Результат запуска `examples/test-config.csv`:

```text
Граф зависимостей (DFS):
A -> B
B -> C
C -> нет зависимостей
```

Для демонстрации есть несколько конфигураций:

```sh
./run.sh examples/test-config.csv
./run.sh examples/diamond-config.csv
./run.sh examples/cycle-config.csv
./run.sh examples/filter-config.csv
./run.sh examples/root-filter-config.csv
./run.sh examples/leaf-config.csv
```

- `test-config.csv` — цепочка A → B → C.
- `diamond-config.csv` — общая зависимость D у B и C; несвязанный Z не обходится.
- `cycle-config.csv` — цикл A → B → C → A и петля B → B.
- `filter-config.csv` — исключение B с сохранением D через C.
- `root-filter-config.csv` — исключение самого корня A.
- `leaf-config.csv` — пакет C без зависимостей.

## Ошибки

Код завершения 0 означает успешную работу, 2 — ошибку CSV или аргументов,
3 — ошибку репозитория или получения зависимостей. При ошибке частичный
граф не выводится. Проверяются структура JSON, имена и наличие пакетов.
Для сети обрабатываются HTTP-ошибки, таймауты и повреждённый индекс.
Таймаут сетевой операции — 15 секунд, лимит ответа индекса — 20 МиБ.

Примеры неверных настроек сохранены в `examples/errors/`, например:

```sh
./run.sh examples/errors/ascii_tree.csv
```

## Файлы и функции

Исходники находятся в `src/`, примеры — в `examples/`, проверки — в `tests/`.
Скрипт `run.sh` запускает приложение.

В `src/config.py` структура `Config` хранит настройки, а `ConfigError`
описывает ошибки их чтения и проверки:

- `read_values` — читает CSV и проверяет наличие параметров.
- `collect_rows` — собирает настройки в словарь.
- `validate_row` — проверяет столбцы, ключи и повторы.
- `validate_printable` — запрещает управляющие символы.
- `parse_bool` — преобразует `true` и `false` в булевы значения.
- `resolve_path` — определяет путь относительно папки CSV.
- `validate_repository` — выбирает проверку URL или локального файла.
- `validate_local_repository` — проверяет чтение локального файла.
- `parse_repository_url` — разбирает адрес, проверяет схему, хост и порт.
- `validate_url_access` — проверяет учётные данные и номер порта.
- `validate_remote_repository` — проверяет URL, включая пробелы.
- `validate_output` — проверяет имя и расширение выходного файла.
- `validate_output_location` — проверяет папку и тип выходного пути.
- `load_config` — проверяет настройки и создаёт `Config`.

В `src/cargo.py` структуры `Package` и `Dependency` хранят сведения
из индекса, `RepositoryError` описывает ошибки данных и загрузки:

- `index_path` — определяет путь пакета в индексе Cargo.
- `fetch_index` — загружает файл индекса по HTTP(S).
- `parse_records` — разбирает строки JSON.
- `validate_record` — проверяет запись версии.
- `stable_version_key` — получает числовой ключ стабильной версии SemVer.
- `select_release` — выбирает последнюю стабильную неотозванную версию.
- `required_text` и `optional_text` — проверяют строковые поля.
- `parse_dependency` — извлекает данные одной зависимости.
- `load_package` — получает пакет и его прямые зависимости.
- `format_dependency` — формирует строку зависимости для вывода этапа 2.

В `src/repository.py` выбирается источник зависимостей:

- `unique_object` — проверяет отсутствие повторных ключей JSON.
- `validate_test_name` — проверяет имя тестового пакета.
- `validate_test_dependencies` — проверяет список его зависимостей.
- `validate_test_repository` — проверяет структуру JSON и ссылки на пакеты.
- `load_test_repository` — читает и проверяет тестовый JSON.
- `test_dependencies` — получает зависимости тестового пакета.
- `normalize_registry` — сопоставляет Git и HTTP-адреса crates.io.
- `validate_dependency_registry` — проверяет реестр зависимости.
- `cargo_dependencies` — получает имена зависимостей Cargo с учётом фильтра.
- `create_loader` — выбирает тестовый или сетевой источник.

В `src/graph.py` тип `Graph` описывает списки смежности,
`DependencyLoader` — функцию получения прямых зависимостей:

- `is_filtered` — проверяет совпадение имени с подстрокой.
- `build_graph` — строит достижимую часть графа стеком DFS без рекурсии.
- `print_graph` — выводит граф списками смежности.

В `src/main.py` функция `analyze` выбирает источник и строит граф,
а `main` обрабатывает запуск, результат и ошибки.

Команда запуска проверок:

```sh
python3 -m unittest discover -s tests -v
```
