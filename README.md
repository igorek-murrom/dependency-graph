# Практическая работа № 2, вариант 16

Программа для работы с графом зависимостей пакетов Rust (Cargo).
На втором этапе она читает настройки из CSV, загружает индекс Cargo
и выводит прямые зависимости выбранного пакета. Используется только
стандартная библиотека Python, без вызова менеджера пакетов.

## Запуск

Нужен Python 3.10 или новее. Дополнительные библиотеки и сборка не нужны.
Команды выполняются из папки проекта:

```sh
./run.sh examples/config.csv
```

Можно запустить напрямую:

```sh
python3 src/main.py examples/config.csv
```

Для загрузки нужен доступ к интернету.
Справка вызывается командой `./run.sh --help`.

## Настройки

Путь к CSV передаётся при запуске. Все настройки задаются внутри файла:

```csv
key,value
package_name,serde
repository,https://index.crates.io/
test_mode,false
output_file,graph.svg
ascii_tree,false
filter_substring,
```

- `package_name` — имя пакета: латинские буквы, цифры, `_` и `-`.
  Первый символ должен быть буквой или цифрой.
- `repository` — HTTP(S)-адрес корня индекса Cargo, например
  `https://index.crates.io/`, без пробелов, учётных данных, query и fragment.
  Адрес Git-репозитория или страницы пакета не подходит. В тестовом режиме
  вместо адреса указывается путь к доступному файлу.
- `test_mode` — работа с тестовым репозиторием: `true` или `false`.
- `output_file` — имя будущего SVG-файла. Папка для него должна существовать.
- `ascii_tree` — вывод зависимостей в виде ASCII-дерева: `true` или `false`.
- `filter_substring` — подстрока для исключения пакетов из анализа.
  Пустое значение отключает фильтр.

CSV должен быть в UTF-8 с заголовком `key,value`. Каждый параметр
указывается один раз. Неизвестные ключи, лишние столбцы и управляющие
символы считаются ошибкой. Значения с запятой нужно заключать в кавычки.
Пути внутри CSV считаются относительно папки этого файла.

Поскольку в варианте 16 версия не задаётся, выбирается последняя
стабильная неотозванная версия пакета по SemVer. Предварительные версии
пропускаются. Индекс читается в формате JSON Lines по правилам Cargo.

Выводятся все объявленные прямые зависимости, включая `normal`, `build`,
`dev`, optional и зависимости отдельных платформ. В строке указаны имя,
требование к версии и условия зависимости. Для переименований используется
настоящее имя пакета. Версии зависимостей пока не разрешаются.

Обход графа и фильтрация относятся к этапу 3, ASCII-дерево и SVG — к этапу 5.
Эти настройки пока только проверяются. Тестовый режим также будет добавлен
на этапе 3; сейчас он выводит сообщение об отсутствии поддержки.
Пример его настроек сохранён в `examples/test-config.csv`.

Пример вывода:

```text
Пакет: serde 1.0.229
Прямые зависимости:
- serde_core =1.0.229 [normal]
- serde_derive ^1 [normal; optional]
```

Версия и зависимости в примере могут меняться после новых публикаций.
Если зависимостей нет, программа сообщит об этом отдельно.

## Ошибки

При неверных настройках программа выводит сообщение об ошибке
и завершается с кодом 2. Ошибки сети и данных репозитория имеют код 3.
При успешном запуске код завершения — 0. Обрабатываются отсутствие пакета,
HTTP-ошибки, таймауты, неверная кодировка и повреждённый индекс.
Таймаут сетевой операции — 15 секунд, лимит ответа — 20 МиБ.

В `examples/errors/` есть примеры ошибок для каждого параметра.
Например:

```sh
./run.sh examples/errors/ascii_tree.csv
```

Результат:

```text
Ошибка конфигурации: ascii_tree: ожидается true или false
```

## Файлы и функции

Исходники находятся в `src/`, примеры настроек — в `examples/`,
проверки — в `tests/`. Скрипт `run.sh` запускает программу.

В `src/config.py` структура `Config` хранит настройки, а `ConfigError`
описывает ошибки их чтения и проверки. Функции этого модуля:

- `read_values` — читает CSV и проверяет наличие параметров.
- `collect_rows` — собирает настройки в словарь.
- `validate_row` — проверяет столбцы, ключи и повторы.
- `validate_printable` — проверяет отсутствие управляющих символов.
- `parse_bool` — преобразует `true` и `false` в булевы значения.
- `resolve_path` — определяет путь относительно папки CSV.
- `validate_repository` — выбирает проверку URL или локального файла.
- `validate_local_repository` — проверяет доступность файла для чтения.
- `parse_repository_url` — разбирает адрес, проверяет схему, хост и порт.
- `validate_url_access` — проверяет учётные данные и номер порта.
- `validate_remote_repository` — проверяет URL, включая пробелы.
- `validate_output` — проверяет имя и расширение выходного файла.
- `validate_output_location` — проверяет папку и тип выходного пути.
- `load_config` — проверяет все настройки и создаёт `Config`.

В `src/cargo.py` структура `Package` хранит выбранную версию пакета,
`Dependency` — сведения о зависимости, `RepositoryError` — ошибку
загрузки или данных репозитория. Функции этого модуля:

- `index_path` — определяет путь пакета в индексе Cargo.
- `fetch_index` — загружает файл индекса по HTTP(S).
- `parse_records` — разбирает строки JSON.
- `validate_record` — проверяет поля записи версии.
- `stable_version_key` — получает числовой ключ стабильной версии SemVer.
- `select_release` — выбирает последнюю стабильную неотозванную версию.
- `required_text` — проверяет обязательное строковое поле.
- `optional_text` — проверяет необязательное строковое поле.
- `parse_dependency` — извлекает данные одной зависимости.
- `load_package` — загружает пакет и получает его прямые зависимости.
- `format_dependency` — формирует строку для вывода зависимости.

В `src/main.py` функция `main` обрабатывает аргументы запуска,
загружает настройки и пакет, выводит зависимости или ошибку.

Команда запуска проверок:

```sh
python3 -m unittest discover -s tests -v
```
